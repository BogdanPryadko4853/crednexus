# CredNexus Frontend

React-кабинет предпринимателя и рабочее место сотрудника банка.

## Запуск

Из корня монорепозитория: `docker compose up --build -d`. Кабинет: http://localhost:5173.
Для локальной разработки: `cd frontend && npm ci && npm run dev`. Настройки перечислены в `.env.example`; Docker получает их из `compose.yaml`.

## Демонстрация

1. Войти через Keycloak. Тестовый пользователь CredNexus: `admin`, пароль по умолчанию задаётся `KEYCLOAK_TEST_ADMIN_PASSWORD` в Compose.
2. На главной добавить синтетическую компанию. Автор становится её владельцем.
3. Сотрудник с `ADMIN` или `BANK_EMPLOYEE` создаёт кредитный продукт на главной.
4. Открыть «Подать заявку», выбрать компанию и продукт, указать сумму и цель, подтвердить создание черновика.
5. В черновике сохранить срок и остальные параметры. Заполнить финансовую анкету; для ИП допустимо 0 сотрудников.
6. Заполнить и сохранить ML-профиль: последний закрытый месяц, отрасль, возраст компании, показатели финансового среза и минимум три месяца фактических наблюдений (рекомендуется 13). Пустая ячейка означает неизвестное значение, ноль вводится явно. Месячные данные не генерируются из годовых итогов. БКИ заполняет backend.
7. После сохранения обязательных разделов отправить заявку. Статусы автоматически обновляются каждые 5 секунд, пока вкладка видима.
8. При уточнении ответить текстом или приложить документ к конкретному документному запросу. PDF, PNG и JPEG — до 10 МиБ; server-side проверка остаётся на backend.
9. При одобрении изучить условия и срок оффера, принять или отклонить. После принятия договор и выдача симулируются автоматически; реального перечисления нет.
10. Сотрудник может открыть очередь ручного рассмотрения, запросить сведения, одобрить, отказать или предложить другие условия. Backend повторно проверяет все права и ограничения.

## Проверки

`npm run build` — TypeScript и production-сборка. `npm test` — Vitest/Testing Library, включая блокировку отправки без ML-профиля, валидацию месячных данных и документные уточнения.

Сквозной сценарий требует запущенных Keycloak, backend, PostgreSQL, MinIO и ML. Ошибки этих сервисов не подменяются успешным результатом на frontend.
