# CredNexus — синтетические данные v2.1 (генератор 0.2.1)

**CI, Docker, healthcheck и CPU fallback:** [конфигурация и проверки](docs/CI.md).
Только ML без БД: `docker compose -f compose.ml.yaml up --build -d --wait` из корня.

**Backend FastAPI + PostgreSQL:** [запуск, бизнес-процесс и очередь ML](docs/BACKEND.md).
Из корня репозитория: скопируйте `.env.example` в `.env`, затем `docker compose -f compose.python.yaml up --build -d`.
Backend и worker устанавливаются через `requirements-backend.txt`; прямой ML API описан ниже.

**HTTP API:** [контракты, запуск и примеры](docs/API.md). Из `ml-service`:

```bash
python -m pip install -r requirements-api.txt
python -m uvicorn crednexus_ml.api:app --host 127.0.0.1 --port 8000
```

Скоринг: `POST /v1/score`, прогноз: `POST /v1/forecast`, готовность:
`GET /health/ready`. Swagger: `http://127.0.0.1:8000/docs`.
Кассовый разрыв: `POST /v1/cash-gap` — [контракт и расчёт](docs/CASH_GAP.md).
Для результатов и кредитных решений добавлены [шаблонные пояснения без LLM](docs/EXPLANATIONS.md).
Для полного набора тестов установите `requirements-test.txt`.

**Готовые модели в Git:** [ONNX для CPU](docs/ONNX.md). После clone можно выполнить `python -m crednexus_ml.onnx_demo` из `ml-service`, установив `requirements-onnx.txt`; большой датасет и native-веса не нужны.

Текущий MVP: XGBoost для основного риска и денежных потоков, LightGBM для 90DPD. [Состав, метрики и причины выбора](docs/DEPLOYMENT.md). Ансамбли сохранены в истории экспериментов.

Обученные CatBoost / LightGBM / XGBoost и эксперимент Chronos-2: [результаты сравнения](docs/TRAINING_REPORT.md), [запуск и inference](docs/MODELS.md). Веса сохраняются локально в `artifacts/`, модели работают на CPU.

Генератор финансовой истории малого бизнеса для скоринга и прогноза денежных потоков. Текущий набор: `data/sme_100k_v2`. Старые `sme_100k_v1`, `pilot_v1`, `smoke_v1` удалены; их агрегированные отчёты оставлены для сравнения.

**Это сценарная синтетика, а не эмпирически откалиброванные российские банковские данные.** Все компании, операции и макропути искусственные. Версия v2 устраняет механические ограничения, выявленные [аудитом v1](docs/ADEQUACY_AUDIT_V1.md).

Повторная проверка v2 выявила массовые длинные нулевые денежные остатки у работающих компаний. В v2.1 добавлена индивидуальная политика сохранения ближайшего операционного резерва из реальных денег и прекращение затяжного непрерывного стресса. [Актуальный повторный аудит](docs/ADEQUACY_AUDIT.md) включает проверку постоянных рядов; прямая линия после закрытия допустима при отсутствии движения денег.

## Что изменилось

- 96 месяцев вместо 60; обучение, validation и test разделены по компаниям **и времени**, с дозревшими кредитными labels.
- Прогнозы каждый месяц на 1/2/3 месяца, все месяцы года для каждого горизонта; исключены пограничные окна.
- Датированные очереди счетов покупателей и поставщиков с 30/60/90-дневными сроками, авансами, частичными и поздними оплатами.
- Запасы, закупки до продаж, ограничения поставщиков при просрочке, различие между покупками, себестоимостью и денежными платежами.
- Устойчивый, низкомаржинальный, растущий, сезонный и сокращающийся бизнес; случайные переходы, неодинаковая сезонность и шум.
- Состояния active/distressed/restructuring/closed, восстановление до закрытия, капитализация процентов в договорные каникулы, ликвидация запасов.
- Операционные задержки кредитных платежей, конечные ресурсы владельца, дополнительные заимствования, неодинаковый эффект инвестиций.
- Отдельные clean / observed / corrupted представления. Ошибки ×100 и дубли больше не являются основными обучающими данными.
- Разная концентрация покупателей B2B/B2C и отдельная концентрация канала продаж.
- Разные макропути для train/validation/test/OOD; скрытые режимы, world и будущие события не входят в признаки.

## Запуск

Python 3.13.11. Из каталога `ml-service`:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-data.txt

python -m crednexus_data.generate --companies 1000 --output data/small_v2
python -m crednexus_data.validate data/small_v2

python -m crednexus_data.generate --companies 100000 --output data/sme_100k_v2
python -m crednexus_data.validate data/sme_100k_v2
python -m crednexus_data.plateaus data/sme_100k_v2
python -m unittest discover -s tests -v
```

Непустой каталог не перезаписывается. Все компоненты генератора работают на CPU без API, сети, весов LLM и платных сервисов. Генерация и валидация пакетные; batch-size по умолчанию 250. Полные месячные таблицы не нужно загружать в pandas сразу: читайте части или `pyarrow.dataset.Scanner`.

Seed, размер пакета, версии библиотек и исходники определяют результат. Изменение batch-size меняет траектории. Manifest фиксирует конфигурацию, схемы, allowlists, целевые переменные, временные когорты и SHA256 всех трёх исходников генерации.

## Таблицы

| Таблица | Назначение |
|---|---|
| `companies` | Синтетические компании, отрасль, возраст, форма, концентрация покупателей/канала, company split |
| `monthly_clean` | Истинные значения пяти наблюдаемых показателей; история до рождения отсутствует |
| `monthly_observed` | Основное представление: небольшие уточнения бухгалтерских значений, пропуски и сбои источника |
| `monthly_corrupted` | Парное стресс-представление с масштабными ошибками/дублями; **не основной train** |
| `score_features` / `score_labels` | Одна заявка на компанию, допущенную по состоянию на origin; входы и targets раздельно |
| `stress/score_features_corrupted` | Парные ошибочные признаки с теми же ID и labels для теста устойчивости |
| `forecast_features` / `forecast_labels` | Ежемесячные origins, горизонты 1–3; прогноз поступлений/операционных выплат |
| `audit/monthly_truth` | Денежный ledger, счета, запасы, долги, состояния, события; **не произвольный источник ML-признаков** |
| `audit/company_parameters` | Скрытые режимы и world для проверки симулятора, не вход модели |
| `audit/credit_outcomes` | Все заявки и причины исключения по доступному состоянию; не вход модели |
| `macro` | Четыре синтетических сценария, не реальные исторические ряды ЦБ |

Деньги в truth — float64, прогнозные числовые признаки — float32. Формат Parquet/Zstandard, одна часть на пакет компаний.

## Целевые переменные

**Основная `default_next12m`:** хотя бы одно событие в следующие 12 месяцев: 90+DPD, вынужденная реструктуризация или закрытие с непокрытым долгом. Это явный сценарный proxy неблагоприятного кредитного события, **не точная регуляторная банковская дефиниция default**.

**Отдельная `default_90dpd_next12m`** сохраняет прежний смысл 90+DPD. Компоненты `distressed_restructure_next12m` и `closure_with_debt_next12m` доступны отдельно. Выбирайте нужный target осознанно; остальные labels не должны попасть в X.

Прогнозные targets: поступления от покупателей, фактически оплаченные операционные счета и их разность. Кредиты, взносы владельца, продажи активов и обслуживание долга не входят в операционный net cash flow. После будущего закрытия продажи/платежи могут исчезнуть, но поступления по старым счетам продолжаются. Эти исходы не удаляются задним числом.

## Временная проверка

Для 96 месяцев:

| Задача / cohort | Origin | Последняя цель |
|---|---|---|
| Credit train | 23–35 | 47 |
| Credit validation | 47–59 | 71 |
| Credit test / OOD | 71–83 | 95 |
| Forecast train | 23–46, допустимые горизонты | 47 |
| Forecast validation | 47–70, допустимые горизонты | 71 |
| Forecast test / OOD | 71–92, допустимые горизонты | 95 |

Максимальная дата обучающего исхода не позже первой даты следующей когорты; прогнозы формируются после закрытия origin месяца. История тестовой компании до origin доступна для её лагов, но не становится обучающими строками. Company split задаётся независимо до симуляции; отбор operating/eligible после этого влияет на фактические размеры cohorts.

Базовые X перечислены в `manifest['scoring_feature_columns']` и `manifest['forecast_feature_columns']`. Можно добавлять отношения и другие производные только из информации, известной на origin; пример — `crednexus_ml.common` и историческое значение за target−12 в обучении прогноза. Не включайте ID, split, world, audit-флаги, будущие макрозначения или другие labels. Для CatBoost категориальные поля скоринга: `sector`, `legal_form`, `purpose`; для прогноза — `sector`.

Прогнозные targets соединяются по `sample_id`, скоринговые — по `application_id`, с `validate='one_to_one'`. Дубли metadata из labels нужно проверять на совпадение, не превращать в дополнительные признаки.

На машине с 8 ГБ RAM первый CatBoost-прогноз обучайте на 100–200 тыс. train-строк и разрешённых колонках. Потоковая генерация миллионов строк не означает, что загрузка всех прогнозных features в pandas вместе с обучением помещается в 8 ГБ.

python -m pip install -r requirements-audit.txt
python -m crednexus_data.audit data/sme_100k_v2

python -m pip install -r requirements-plots.txt
python -m crednexus_data.plot data/sme_100k_v2

Аудит обучает небольшие диагностические CPU-модели для обеих дефиниций кредитного исхода, проверяет corrupted-test и прогноз на выборке строк, сравнивает с seasonal-naive. Модели не сохраняются и не подключаются к приложению. Validation/test не используются для настройки этих фиксированных моделей.
