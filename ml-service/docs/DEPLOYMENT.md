# Рабочие модели MVP

В `models/onnx` находятся четыре одиночные модели. Ансамбли остаются сравнительным экспериментом; они не входят в текущий комплект приложения.

| Задача | Модель | Validation tune | Test из benchmark |
| --- | --- | --- | --- |
| `default_next12m` | xgboost | AP 0.8033 | AP 0.8119; ROC-AUC 0.9599 |
| `default_90dpd_next12m` | lightgbm | AP 0.7945 | AP 0.7611; ROC-AUC 0.9743 |
| `cash_inflow_target` | xgboost | WAPE 19.09% | WAPE 19.64% |
| `operating_cash_outflow_target` | xgboost | WAPE 14.80% | WAPE 15.49% |

Выбор согласован после сравнения качества и сложности интеграции. XGBoost используется для основного скоринга и двух денежных потоков, чтобы упростить поддержку. LightGBM выбран для отдельного 90DPD-таргета: он лидировал среди одиночных моделей по validation AP. Это четыре отдельно обученных модели, а не одна модель с четырьмя выходами.

## Компромисс качества

Для основного скоринга CatBoost был лучше XGBoost на validation AP: 0,8074 против 0,8033. На ранее просмотренном test XGBoost получил AP 0,8119 против 0,8085. Поэтому текущий выбор XGBoost — продуктовый компромисс в пользу простоты стека, а не победитель по валидации. Не следует выдавать уже изученный test за новое независимое подтверждение выбора.

Ансамбль основного риска имел test AP 0,8129; у одиночного XGBoost — 0,8119. Для поступлений WAPE увеличивается с 19,52% до 19,64%, для выплат — с 15,38% до 15,49%. Эти небольшие различия не проверялись на статистическую значимость. Полное сравнение всех кандидатов, стрессовые метрики и эксперимент Chronos-2 находятся в [TRAINING_REPORT.md](TRAINING_REPORT.md).

## Калибровка и происхождение

Веса деревьев не переобучались: используются обученные native-модели из benchmark. Для каждого классификатора взята его собственная Platt-калибровка на отдельных validation-компаниях; калибратор ансамбля не переносится на одиночную модель. Интервалы денежных потоков заново рассчитаны по остаткам выбранных XGBoost на отведённых для калибровки validation-компаниях.

Фактическое покрытие 90%-интервалов: около 90,1% для поступлений и 89,8% для выплат на test; 88,3% и 88,8% на stress. Это эмпирические результаты, без гарантии покрытия при временном дрейфе.

В ONNX встроены категориальные ветвления, масштабирование, отсечение отрицательных денежных прогнозов и калибровка вероятностей. Прогнозные интервалы рассчитывает загрузчик. Исходные признаки и API загрузчика сохранены. Проверка native/ONNX включает по 3200 строк на задачу с validation/test/stress, пропусками и неизвестными категориями. Численные различия XGBoost из-за суммирования float32/double отражены в `verification.json`.

Данные полностью синтетические. Указанные числа описывают benchmark прототипа и не подтверждают пригодность для реального кредитного решения.

## Запуск и файлы

Инструкция: [ONNX.md](ONNX.md). Демо работает сразу после clone, без большого датасета и native-библиотек:

```bash
cd ml-service
pip install -r requirements-onnx.txt
python -m crednexus_ml.onnx_demo
```

В Git включены ONNX, schemas, registries, контрольные суммы, демопримеры, `deployment_policy.json`, `selected_model_metrics.json`, `interval_metrics.json` и provenance. Генератор, обучение и все сравнительные разработки также остаются в репозитории. Большие датасеты, native-эксперименты и виртуальное окружение игнорируются.
