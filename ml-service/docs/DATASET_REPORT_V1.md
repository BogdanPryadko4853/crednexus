# Сгенерированный набор: sme_100k_v1

Набор находится в `ml-service/data/sme_100k_v1`, полностью синтетический, Parquet + Zstandard. Большие файлы исключены из git через локальный `.gitignore`; исходники, документация и агрегированный анализ источников остаются в git. Для восстановления выполнить команду из README с `--companies 100000`, остальные параметры по умолчанию.

## Размер

| Таблица | Строк |
|---|---:|
| Компании | 100 000 |
| Месячная история наблюдений | 6 000 000 |
| Месячный истинный ledger для аудита | 6 000 000 |

Все признаки, labels, audit и диаграмма вместе занимают примерно 1.64 ГБ (1.53 ГиБ) на диске. Число прогнозных примеров не означает 3.6 млн независимых компаний: горизонты и соседние окна связаны.

## Исходы и события

- Среди 99 394 допустимых заявок — 1 170 случаев будущего 90+DPD, около **1.18%**.
- 606 компаний с текущими 90+DPD на дату заявки исключены из обучающих кредитных примеров и сохранены в аудите.
- 420 296 активных company-month записей имеют флаг начала экономического события.
- 269 716 company-month записей имеют хотя бы один флаг ошибки наблюдения; события и ошибки могут пересекаться.
- Пропуски до рождения компании не считаются ошибками.

| Credit split | Допустимых заявок | Defaults | Доля |

Доли естественно возникли из сценарной экономики. Они не подгонялись под публичные значения банкротств или долю просроченной задолженности ЦБ.

## Воспроизводимые проверки

Полная валидация сохранена в `validation_report.json` внутри каталога данных. Проверены денежные равенства, временные окна, отсутствие будущих значений в лагах, доступность исторических снимков, разделение компаний и пересчёт labels.

Для ориентира seasonal-naive baseline на строгом test (новые компании и будущие месяцы) даёт WAPE около 33.1% по поступлениям и 32.9% по оплаченным операционным расходам. Прогноз строится из **наблюдаемой** истории с ошибками, а цель — из истины; baseline оценивается по строкам, где его прогноз не пропущен. Это не результат обученной модели.

Измерения в текущем окружении (`/usr/bin/time -v`): генерация — 31.76 с, peak RSS 334 276 КиБ (~327 МиБ); проверка — 13.30 с, peak RSS 739 616 КиБ (~722 МиБ). Скорость на другом CPU/диске отличается. Эти измерения относятся к генератору/валидатору, а не к обучению CatBoost или всему приложению.

Изображение: `dataset_overview.png` внутри каталога набора. `manifest.json` содержит схемы и разрешённые признаки. Публичные источники численно проанализированы отдельно: [reference_profiles.json](reference_profiles.json).

## Что ещё не сделано

Модели на этом наборе не обучались. Генератор не откалиброван на реальных российских клиентских историях. Перед дальнейшим усложнением стоит проверить baseline CatBoost, ошибки на stress-test и чувствительность к параметрам симулятора; большой объём сам по себе не гарантирует реализм.
